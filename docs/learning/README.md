# CargoFlow для фронтендера

Короткий курс по этому бэкенду для тех, кто знает JS/TS и REST, но не знает Go и gRPC. Читать по порядку, каждая глава — 5–10 минут.

1. [Go глазами TypeScript-разработчика](01-go-for-frontend.md) — синтаксис и идеи Go, которые встречаются в проекте.
2. [gRPC за 10 минут](02-grpc.md) — что это, чем отличается от REST и зачем он здесь.
3. [Карта проекта](03-project-map.md) — зачем нужна каждая папка и каждый файл.
4. [Путь одного запроса](04-request-journey.md) — что происходит от `fetch('/v1/shipments')` до записи в базу и уведомления.
5. [События и инфраструктура](05-events-and-infra.md) — NATS, outbox, Postgres, Redis, Docker, Makefile, трейсинг.
6. [Как что-то поменять](06-recipes.md) — пошаговые рецепты: новое поле, новый эндпоинт, отладка.

## Вся система на одной картинке

```
             ТЫ (React)
                │  fetch, JSON, REST — как обычно
                ▼
        ┌───────────────┐
        │    gateway    │  единственная «дверь» наружу: проверяет токен,
        │     :8080     │  переводит REST → gRPC
        └──┬─────┬────┬─┘
     gRPC  │     │    │  gRPC (внутренняя сеть, браузер сюда не ходит)
           ▼     ▼    ▼
        auth  shipment  tracking          ← каждый со своей базой
                 │          ▲
                 │ события  │ события
                 ▼          │
           ┌──────────────────┐
           │  NATS (очередь)  │───────▶ notification (шлёт уведомления)
           └──────────────────┘
```

Пять сервисов — это пять отдельных программ. Каждая запускается сама по себе, у каждой своя ответственность, они общаются по сети. Это и есть «микросервисы».

Для фронта всё это выглядит как обычный REST API на `http://localhost:8080` с OpenAPI-спецификацией на `/openapi.json`.
